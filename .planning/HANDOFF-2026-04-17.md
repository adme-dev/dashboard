### Enterprise Advisor (Phases 1–5)

**Phase 1 — Backlog core.** Migration `068-recommendations.sql` (recommendations + recommendation_events + recommendation_outcomes). Advisor generation auto-inserts one row per rec linked to `source_report_id`. Endpoints under `/api/advisor/recommendations/`: list (with status/priority/client/period/assignee filters), detail (+ events + outcomes), PATCH (status/assignee/notes/etc with audit trail), POST `/events`. New `/advisor` page with UTable + filter bar + detail slide-over with inline edit controls.

**Phase 2 — Vectorize.** `server/utils/advisorEmbedder.ts` — `embedRecommendation()` generates Workers AI `bge-base-en-v1.5` 768-dim embedding, upserts to `agency-search` Vectorize index with `metadata.type='advisor-rec'` + tenant/client tags, persists `vector_id`. `searchSimilarAdvisor()` queries with metadata filter. Advisor generation fires embed per rec. Prompt now injects up to 10 open/in-progress carry-over recs. `POST /api/advisor/recommendations/backfill-embeddings` (admin, force=1 to re-embed). `GET /api/advisor/recommendations/similar?id=X` (top-5 hydrated neighbors). Drawer shows "Related past advice" with similarity scores and click-to-navigate.

**Phase 3 — Relationship graph.** `GET /api/advisor/recommendations/:id/graph` returns `{nodes, edges}` traversal (client, report, metric, assignee, outcomes, events, up to 3 Vectorize neighbors). `app/components/advisor/Graph.client.vue` — radial SVG node-link viz, typed node colors + legend, click-to-navigate.

**Phase 4 — Impact attribution.** `server/utils/advisorMetrics.ts` — 15-metric registry (`METRIC_REGISTRY`) mapping name → endpoint + JSON path + preferred direction + unit. `fetchMetricValue(event, metric, toDate, extraHeaders?)`. Advisor LLM prompt extended to optionally emit `target_metric` + `target_direction`; baseline pulled from snapshot via `SNAPSHOT_PATHS` and persisted. `POST /api/internal/attribution-cron` finds done recs past 30/60/90d checkpoints, re-measures via `fetchMetricValue`, writes `recommendation_outcomes` (idempotent per checkpoint). Outer auth via `ATTRIBUTION_SECRET`; narrow middleware bypass (`X-Internal-Cron-Secret` → `CRON_INTERNAL_SECRET`) enables cron to hit Xero/advisor read endpoints without a session. Drawer gets Impact attribution panel with baseline → measured strip, pass/fail coloring vs target direction, metric-unit-aware formatting.

**Phase 5 (partial) — Multi-client scope.** Migration `069-client-xero-connections.sql` scaffolds per-client Xero connections (awaiting OAuth flow). `server/utils/advisorClientSnapshot.ts` derives client-scoped snapshot from tracking-category P&L + contact-matched aging + recurring invoices. Advisor endpoint accepts `?clientId=X`: scoped snapshot, client-facing prompt variant, recs inserted with `client_id`, embeddings tagged, cache + carry-over scoped per-client. `/advisor` navbar has a URL-persisted scope selector; `/reports` advisor slide-over has a scope row that triggers re-generation.
