# Native customer editor handoff foundation — RND-22

Continue the approved customer CMS journey. The existing editor token and mutation stack only support agency/portal actors; standalone customers must not be represented as either identity. Implement the native handoff boundary first, without exposing a premature editor button or changing existing editor authorization.

1. Add a replayable migration for short-lived, single-use customer handoff receipts. Store only a digest of the random secret, native login hash, identity/workspace/site, exact trusted origin pair and expiry. Prevent changes to immutable scope or extending expiry. Keep consumption atomic and monotonic.
2. Implement internal issue/redeem services. Issue derives all scope from native completed setup and an approved existing preview; no allocation. Use current native login and ownership/policy authority. A secret is exchanged only by a future authenticated private Studio adapter with its configured origin pair. Recheck current access before consuming; return only a typed customer context with fixed dashboard return URL. This context is not an editor session or readiness proof. No public route or legacy token conversion is added.
3. Use real PostgreSQL tests for expiry, replay, concurrent redemption, wrong origins, changed scope, logout, membership/identity/entitlement revocation and immutability. Apply the additive migration twice to the owned local database. Verify the legacy editor claims parser rejects the opaque handoff and no consumer bypass exists.
4. Run regression/typecheck/lint checks and one fresh final review. Push a draft stacked PR and update the canonical PRD with remaining work: paired customer-aware Studio session/typed checkpoint adapter, runtime/storage verification and browser launch/return acceptance.

Threat model: stolen/replayed handoff; foreign origin/redirect; forged caller scope; authority revoked between issue and consume; races against logout and entitlement expiry. Hash storage, strict configuration, native locks, database clock and atomic compare-and-consume address these. No external URL fetches, billing, source editing, publication, production migration or deployment.
