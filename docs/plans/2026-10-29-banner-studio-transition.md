## Autosave and saved viewer — 29 October 2026

The prior editor displayed Saved/Unsaved changes but did not schedule autosaves. This follow-up adds a two-second editing debounce with a ten-second maximum interval, serialized saves, fifteen-second retry on failure, and navigation protection while changes remain unsaved. Project-title typing follows the same path; client reassignment remains an explicit Apply client action. New drafts clear the previous singleton project identity. Failed project loads do not expose the previous design for editing.

Each editor save first persists the project, then asks the server to store the accepted database revision as a content-addressed JSON snapshot in R2 (`banner-snapshots/<project>/<sha256>.json`). Only after both requests succeed does the editor clear its dirty state. The authenticated saved viewer resolves the latest database revision, checks project/client access, reads and verifies that exact bucket object, and refreshes every five seconds. It does not use a mutable latest-object pointer that slower requests could overwrite. Existing projects need their next editor save to create their first viewer snapshot. Published ads and downloadable exports retain their existing explicit flows.

Local browser acceptance used the complete editor and an existing MU-X MP4 placed as a background in an isolated test project: title and text autosaved without clicking Save, the viewer refreshed, reopening retained the video source, the video decoded at 1920×700 and advanced through the eight-second preview. This is video-layer save/view acceptance, not a successful import of a TheBrief video-background project or an MP4 export certification. Local files and screenshots remain outside Git.
