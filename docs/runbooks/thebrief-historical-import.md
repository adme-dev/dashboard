# TheBrief historical import dates and batches

Updated 24 November 2026. Banner Studio accepts the original TheBrief HTML5 group ZIP directly, including multiple designs and their sizes. Prepared `.xeroflow.json` files remain supported. Work in small groups within the current bounds: 64 MiB source ZIP, 50 designs, 20 sizes per design and 128 MiB aggregate prepared selection. Large or complex designs may need smaller groups. See the [canonical import runbook](thebrief-banner-import.md) for conversion boundaries and current media limits.

1. Inventory one TheBrief workspace or folder at a time. Reconcile every design set and size against Banner Studio and the saved migration ledger before exporting or importing. Preserve existing projects and edits.
2. Record the **Created** date for each design from TheBrief's design Info panel, alongside its design identity and folder. The [TheBrief design Info guide](https://help.thebrief.ai/hc/en-us/articles/22638477185948-How-to-preview-comment-on-designs) identifies this as the source of the creator and creation date. Preserve the folder list's **Last modified** date and user in the migration ledger too, as separate source metadata for a later library update. ZIP timestamps, export filenames and download time are not creation dates.
3. Select the agreed designs and export HTML5 with General usage, all required sizes and custom-font-to-SVG disabled. Retain the original group ZIP and SHA-256. Upload that ZIP without extracting or renaming it. Offline package preparation is now a diagnostic route for conversion holds, rather than a routine designer handoff.
4. In Banner Studio choose **Import creative packages → Choose TheBrief ZIP or prepared packages**. Wait for preparation, reconcile every design and size, then use **Assign the group** to apply the confirmed client and folder. Check each row, especially mixed-client groups. Enter the verified original creation date. The importer holds new drafts without a creation date unless the operator explicitly ticks **Import undated drafts and backfill the date later**; those drafts are tagged `import:created-date-pending` and no date is assigned. A package may carry `source.clientName` from the migration ledger; it preselects a client only when exactly one accessible client has that name, and the operator still confirms it. Matching source-design receipts for the selected client reconcile existing drafts; names alone do not establish identity. Use **Update imported draft** for eligible corrections. Save as drafts, then review artwork, fonts, all sizes, animation and sound against the source. Do not publish historical offers during migration.
5. Record source design ID/hash, folder, original creation date and evidence location, source last-modified date and user, ZIP hash, package hash, saved project ID, review outcome and any blocker in the migration ledger. Continue with the next folder or batch.

The original creation date is stored as a `source-created-date:YYYY-MM-DD` provenance tag. XeroFlow's `created_at` remains the actual project creation timestamp. The library shows both source creation and last modification, and offers an oldest-created sort. Earlier TheBrief imports without a verified source date display **date unverified**; reconcile and backfill them separately against TheBrief Info evidence. Do not replace missing dates with the last-updated or upload date.

The importer waits for the client and folder lists before accepting files. Managed asset uploads run one at a time to bound edge memory. On failure, later uploads stop; acknowledged uploads remain reusable within that dialog. Existing duplicate and uncertain-project checks still apply. A preparation failure leaves the ZIP and saved projects unchanged; start a fresh batch to retry. Record repeated failures with the source archive and exact message. An unsupported size holds its whole design while other compatible designs remain available.

After verifying a new draft, the importer creates its saved viewer from the accepted database revision and reads it back before showing **Open saved viewer**. A storage failure retains the draft and lets the batch continue. **Prepare saved viewer** retries that snapshot without creating another project or uploading the media again; it also prepares an existing accessible draft selected by duplicate reconciliation. All viewers still need a comparison with the original before production use.

Multi-size packages resolve each managed font alias by family, weight and style. Shared font bytes are deduplicated without forcing another size's additional weight onto the wrong face.

## Video layers

Muted, autoplaying TheBrief video converts to an editable native video layer. Static video colour filters and nested opacity are preserved with the outer layer blend mode; nested blend groups, spatial filters and animated filter composition remain held. The original H.264 MP4 bytes are packaged unchanged; `package-import.mjs` uses `ffprobe` to confirm the codec, that the source clip end falls within the file, and that a cover-cropped frame matches the file's aspect. The layer keeps a media clock (`mediaStart`, `mediaEnd`, `mediaLoop`) shared by editor playback, scrubbing, overview and both HTML exporters (`shared/bannerVideoClock.ts`): clips play at normal speed, looping clips restart at their out-point and non-looping clips hold their last frame. TheBrief's cover-crop framing (an oversized `<video>` shifted inside a clipping box) becomes native cover fit with a focal point.

These remain explicit holds: non-zero clip start, click-to-play, sound on hover, playback past the slide, audible video, delays that differ from the layer's presence, rotation or zoom beyond cover, rounded video and non-H.264 files. MP4 entries have a separate inspection allowance of 24 MiB per clip, within the existing 64 MiB archive/video aggregate bounds; every other file keeps its standard limits.

## Text outlines

Outlined text preserves the source paint order as `textPaintOrder`: `fill` paints the stroke over the glyph fill, while `stroke` paints the fill over the stroke. The importer accepts either order and carries it through editable text and both HTML exporters. Existing Banner Studio text without this property retains its previous stroke-first appearance. Other source paint sequences remain held. Compare outlined lettering at each affected slide as part of the motion audit.

## Soft shapes

A shape with uniform corner radii of 50% or more becomes a native ellipse (`rectShape: 'ellipse'`), and a static CSS filter on the shape, such as the `blur(8px)` TheBrief uses for ground shadows, carries across as the layer's `visualFilter`. Both are editable in the rectangle inspector and render identically in the editor and both HTML exporters. Uniform solid bordered shapes use editable native button geometry with empty text. Partial-percentage or unequal corner radii, shape box shadows, asymmetric or filtered border compositions and unsafe filters remain held for conversion review.

A successful upload is not a motion pass: compare every size with the original HTML5 export at entry, mid-point, just before the loop and just after it before marking a design verified.
