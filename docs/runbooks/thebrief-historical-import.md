# TheBrief historical import dates and batches

Updated 31 October 2026. TheBrief support recommends selecting about 50 designs per bulk HTML5 export to avoid browser timeouts. Banner Studio accepts up to 50 **prepared** `.xeroflow.json` packages per import batch; it does not accept the export ZIPs directly. A package remains limited to 45 MB. Repeat batches for the full archive.

1. Inventory one TheBrief workspace or folder at a time. Reconcile every design set and size against Banner Studio and the saved migration ledger before exporting or importing. Preserve existing projects and edits.
2. Record the **Created** date for each design from TheBrief's design Info panel, alongside its design identity and folder. The [TheBrief design Info guide](https://help.thebrief.ai/hc/en-us/articles/22638477185948-How-to-preview-comment-on-designs) identifies this as the source of the creator and creation date. Preserve the folder list's **Last modified** date and user in the migration ledger too, as separate source metadata for a later library update. ZIP timestamps, export filenames and download time are not creation dates.
3. Bulk export about 50 designs at a time as HTML5, with custom-font-to-SVG disabled. Retain each original ZIP and SHA-256. Inspect and prepare each supported design with `scripts/thebrief/package-import.mjs`; pass the verified `YYYY-MM-DD` creation date as its final argument after the source folder. Use the same date for all sizes of a design set before `scripts/thebrief/merge-packages.mjs`.
4. In Banner Studio, choose up to 50 prepared packages. Confirm client, folder and original creation date for every assigned design. The importer holds new drafts without a creation date unless the operator explicitly ticks **Import undated drafts and backfill the date later**; those drafts are tagged `import:created-date-pending` and no date is assigned. A package may carry `source.clientName` from the migration ledger; it preselects a client only when exactly one accessible client has that name, and the operator still confirms it. A fresh export of a design already imported for the same client (same `source-design`) is skipped rather than duplicated; use **Update imported draft** for corrections. Save as drafts, then review artwork, fonts, sizes and animation against the source. Do not publish historical offers during migration.

   Each package is checked on its own and shown as **Ready**, **Needs attention** (with the reason: no client, no creation date, a second package for the same design in the batch, or an existing draft that lacks some of its sizes) or **Invalid** (with the validation error). Only Ready packages are imported, one at a time. A failure marks that design **Failed** and the rest continue; its **Retry** is safe because the server returns the existing draft for the same client and source checksum, or for the same client and source design when every prepared size is already in that draft. A fresh export that adds sizes is never merged into an existing draft: it needs attention and uses **Update imported draft**. Progress is recorded in the banner library itself, so reselecting a batch in any browser shows designs already saved as **Saved** and imports only the rest.
5. Record source design ID/hash, folder, original creation date and evidence location, source last-modified date and user, ZIP hash, package hash, saved project ID, review outcome and any blocker in the migration ledger. Continue with the next folder or batch.

The original creation date is stored as a `source-created-date:YYYY-MM-DD` provenance tag. XeroFlow's `created_at` remains the actual project creation timestamp. The library shows both source creation and last modification, and offers an oldest-created sort. Earlier TheBrief imports without a verified source date display **date unverified**; reconcile and backfill them separately against TheBrief Info evidence. Do not replace missing dates with the last-updated or upload date.
