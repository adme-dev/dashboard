## Preserved edit and approval authority

Ordinary saves, named versions and render snapshots copy the exact server-owned obligation contract into the successor timeline revision. Removing clip metadata, clips or tracks does not remove that contract. Saves record affected review reasons against the last reviewed baseline. Explicit version restoration now identifies the saved server version, creates a successor draft and carries that version's obligations; posting historical state alone is an ordinary edit and retains the current obligations.

`GET /api/agency/video/projects/:id/storyboard/timeline-review` loads the current cut, obligations, affected changes, canonical approved copy, eligible current reference candidates and current findings. `POST` accepts an operation identity, timeline/edit preconditions, explicit mappings and optional existing copy revision. Review validates the saved cut and writes immutable evidence without replacing clips. A project lock serializes review, save and competing pointer changes. Operation replay returns its historical review receipt; a new stale review fails with 409. Multiple immutable reviews may exist for one unchanged cut so corrected external dependencies can be reviewed without a fake edit.

The recovery action remains available when new storyboard entry is disabled. It can explicitly approve revised copy or currently eligible references needed by the saved cut. Copy approval requires the prior copy hash and creates an immutable, edit-bound copy record; it does not alter the active plan. Reference approval requires a canonical current hash and human evidence, preserves existing reference roles and untouched decisions, and excludes sources not used by this cut. The recovered reference set is attached only to the immutable review and inherited timeline lineage; it does not advance the storyboard’s global reference pointer. It pins the then-current global authority token, so a later global decision change, including revocation, requires fresh review. Canonical source and actor eligibility continue to be checked live. All approval records roll back if the resulting edit fails validation. Flag-off inline reference recovery is limited to media and Banner sources needed by the cut. A changed pinned brand kit still blocks rendering and requires the existing flag-enabled reference workflow; universal flag-off brand-kit correction remains deferred. Owner requests use the existing God Mode transaction coordinator. No recovery action invokes planning, AI or media generation.

## Render inputs and current eligibility

Render preparation independently resolves each requested output format. It checks current canonical source identity/usage authority, measured media bounds, complete voice recordings against approved speech, exact caption content and required Banner text. Added media needs explicit reference approval and review. Invalid text cannot be approved by changing the review baseline. Optional clip provenance never grants approval.

The dispatch/worker integration creates an immutable job manifest and private job-specific input copies with SHA-256 verification. The worker loads that manifest from storage rather than trusting queue-supplied state. An authenticated application callback checks current dependencies at processing and before publishing, with publication committed while SQL authority/source fences remain held. SQL fences do not freeze external R2 objects: conditional reads, pinned bytes and container hash verification protect the actual rendered inputs. Hosted binding/secret deployment and remote execution remain unverified.

## Supported copy rendering and practical limits

Required copy uses static Chromium overlays. Captions follow this same measurement/capture path instead of the legacy FFmpeg text wrapper, preserving the complete supplied string and whitespace. Only the default caption style is currently supported for obligated renders; other styles fail with an actionable finding. Preview uses the existing editor presentation, while obligated render captions use the measured Arial layout with an explicit opaque black contrast plate. This measured default-caption treatment is not applied to user-authored Banner styling; insufficient Banner contrast blocks review until corrected. This difference is not visual acceptance of the integrated application.

The current supported scope is conservative:

- Static, self-contained copy using Arial/Liberation Sans and verified Latin/basic punctuation coverage. Unsupported scripts remain unchanged but block rendering. External/custom fonts, animation, video/audio/active embedded documents and unverified resources fail closed.
- Each required-copy clip is limited to 60 seconds. A longer clip receives `copy_clip_duration_unsupported` with an instruction to shorten it and review again. Storyboards may still total 120 seconds using separate copy cues within the per-clip limit.
- Required text must have verified foreground/background contrast of at least 4.5:1 against an opaque solid backing. Unsupported CSS clipping, bidi overrides, transformed/pseudo-element text and whitespace collapse fail closed. User-authored Banner colors are not rewritten.
- Each format is measured separately. Missing fonts, clipped or overflowing glyphs, invisible text, incompatible placement and covering siblings block acceptance. There is no truncation, ellipsis or guessed fallback font.
- Required copy surfaces may not overlap in time. This intentionally blocks even spatially separate simultaneous surfaces because separate-page measurement cannot prove final composite visibility.
- Total pinned input transport is bounded to 16 MiB. Larger media needs a future streaming container transport; increasing the limit alone is not an accepted fix.
- Local macOS Chromium/FFmpeg evidence is distinct from the shipped Linux container and authenticated/hosted acceptance. No such acceptance is implied by local fixtures.
