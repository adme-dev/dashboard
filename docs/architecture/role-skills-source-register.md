## Application authority and adaptation boundaries

Registry metadata should distinguish publisher, repository, exact source revision/path, license, review status and adaptation notes. Application versions are immutable records; editing creates a new version and active mappings select an exact version. A role binding selects workflow guidance and never grants a tool, permission group, client, department or evaluated release.

Treat a selected guide as bounded user-selected task data. Do not elevate editable guide text or fetched documentation into privileged system instructions. Keep native effective-catalog composition, explicit Finance grants, read-only policy, user-disabled tools and confirmation checks intact. No workflow can approve its own consequential action or activate an employee pack.

Documentation lookup should use HTTPS GET, exact approved hosts and path families, final-target and redirect-hop validation, response-size/time limits and no model-supplied arbitrary destination. Do not forward application cookies, credentials or customer data to provider documentation servers. Record source URL, retrieval time, status, relevant excerpt and digest; missing, throttled and empty responses remain explicit limitations. Retrieved text is untrusted reference material, never a command to execute scripts, install packages, reveal secrets or change advertising configuration.
