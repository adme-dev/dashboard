# Customer portal domain configuration

This slice adds signed-in client domain configuration to the existing attachment journal. It is local and unreleased pending independent review and the Pages bundle-size gate. Base: main78bf3ddd24bef1e2f639243e9160257df68bc82f, which includes migration419 recovery.

Eligible active customer administrators/managers with exact website editor membership can connect a hostname and request verification. Viewers can read bounded DNS/TLS instructions. Each mutation phase freshly checks selected client, persisted user role and membership, site and effective domain entitlement inside the existing locked transactions. Portal-created domains leave the nullable agency-staff created_by field empty and record the actual client actor in the audit log. No schema migration is needed. Provider IDs, opaque owner metadata and attempt receipts are excluded from portal responses.

The existing portal Domains and DNS navigation now leads to a website selector and the shared Nuxt UI workspace. The selector remounts the workspace on a website change, so data/capabilities belong to the selected site. The page scrolls vertically; DNS values wrap, the connection dialog fits narrow screens, and viewers have no mutation controls. Website configuration does not publish the site or change customer DNS/email records.

Validation: real disposable PostgreSQL covers agency regressions and portal read/write roles, selected-client isolation, audit attribution, revocation around external effects, lost-response recovery and effective entitlement expiration. API tests reject caller scope/actor fields, invalid bodies and unknown provider errors. Browser evidence uses actual source components/Nuxt UI/Geist with synthetic in-memory responses only; no real sessions or external requests. Full authenticated production acceptance remains required after a reviewed release.

Still outstanding: exact provider metadata/list capability readback; safe publish/delivery domain-authority coupling; journaled detach and provider deletion; cutover and rollback against the customer's chosen hostname and current DNS provider; email configuration and recipient decisions. A domain lifecycle marked active represents its DNS/provider/TLS state, not independent proof of a live approved release. Those operations are not implemented or implied by this portal slice. Deployment remains blocked on sufficient immutable Worker bundle headroom; do not raise or bypass that guard.

## Private management service extraction

The portal configuration is composed with email settings in `workers/page-studio-management`. Domain reservation/attempt/receipt SQL, provider calls, DNS verification, fresh portal membership and staff permissions, and domain read queries execute inside this private Worker using fresh Hyperdrive transactions. Pages retains authenticated HTTP parsing and strict RPC contracts. Worker environment bindings supply the provider token, zone and CNAME target; neither callers nor process environment fallback select these values. Lost RPC writes are never retried automatically. Existing domain ownership metadata and journal/state remain persisted unchanged. Portal lists expose bounded DNS/TLS instructions; agency lists use the same instructions projection, while aggregate monitoring and agency verification retain their existing status fields.

The portal hostname input is streamed with a 2048-byte observed limit, cancellation on overflow and fatal UTF-8 decoding. This replaces the former post-buffer length check. Three portal site routes and two mutations are recorded in the route inventory; domain/email authority moved out of the Pages lexical gate inventory and is covered by private RPC and real PostgreSQL tests.

No Cloudflare customer-hostname provider configuration exists in either current Pages environment, as independently read back by the parent. The private Worker remains provider-unconfigured until the real zone, target and secret are selected. Pending database registration is not live provider provisioning, domain cutover, publication, or email delivery. Safe detach, current-release domain routing and live customer DNS acceptance remain outstanding. No provider/DNS/database production changes were made for this extraction.
