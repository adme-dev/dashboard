# Environment Variables Setup - Quick Guide

This guide will help you set up environment variables for both local development and Cloudflare Pages deployment.

## 📋 Prerequisites

1. **Node.js** installed (v20+)
2. **Wrangler CLI** installed: `npm install -g wrangler`
3. **Cloudflare account** with Pages access
4. **Neon database** created (get pooled connection string)

---

## 🚀 Option 1: Local Development (Recommended for testing)

### Step 1: Set up local environment file

```bash
# Run the setup script (generates random secrets automatically)
pnpm env:setup:local

# Or manually
cp .dev.vars.example .dev.vars
```

### Step 2: Edit `.dev.vars` with your actual values

Open `.dev.vars` and add:

```bash
# Required - Get from Neon console
DATABASE_URL=postgresql://user:pass@ep-xxx.neon.tech/db?sslmode=require

# Required for magic links - Get from resend.com
RESEND_API_KEY=re_your_actual_key

# Optional - Get from developer.xero.com
XERO_CLIENT_ID=your_xero_client_id
XERO_CLIENT_SECRET=your_xero_client_secret
```

### Step 3: Start development server

```bash
# Option A: Use Wrangler (loads .dev.vars automatically)
pnpm dev:wrangler

# Option B: Standard Nuxt dev (uses .env)
pnpm dev
```

---

## 🌐 Option 2: Cloudflare Pages Deployment

### Step 1: Login to Wrangler

```bash
npx wrangler login
```

### Step 2: Set up environment variables

```bash
# Interactive setup (recommended)
pnpm env:setup

# Or manually set each secret
npx wrangler pages secret put DATABASE_URL --env production
npx wrangler pages secret put JWT_SECRET --env production
npx wrangler pages secret put SESSION_SECRET --env production
npx wrangler pages secret put RESEND_API_KEY --env production
# ... etc
```

### Step 3: Deploy

```bash
# Deploy to preview environment
git push origin your-branch

# Or manually deploy to production
pnpm deploy:production
```

## 🔧 Manual Secret Management

### List all secrets
```bash
# Development
npx wrangler pages secret list --env development

# Production
npx wrangler pages secret list --env production
```

### Set a single secret
```bash
npx wrangler pages secret put DATABASE_URL --env production
# Enter value when prompted
```

### Delete a secret
```bash
npx wrangler pages secret delete DATABASE_URL --env production
```

## 📁 Environment File Structure

```
├── .env                    # ← Local non-secrets (gitignored)
├── .env.example            # ← Template (committed)
├── .dev.vars               # ← Local secrets for Wrangler (gitignored)
├── .dev.vars.example       # ← Template (committed)
└── wrangler.toml           # ← Non-secret config per environment (committed)
```

## 🔑 Required Variables Checklist

### For Local Development
- [ ] `DATABASE_URL` - Neon pooled connection string
- [ ] `JWT_SECRET` - Auto-generated by setup script
- [ ] `SESSION_SECRET` - Auto-generated by setup script
- [ ] `RESEND_API_KEY` - For magic link emails (optional but recommended)
- [ ] `GTM_GOOGLE_CLIENT_ID` / `GTM_GOOGLE_CLIENT_SECRET` - Dedicated Google Tag Manager Management API OAuth client

### For Production
- [ ] `DATABASE_URL` - Same as above
- [ ] `JWT_SECRET` - Use a new random secret (don't reuse dev)
- [ ] `SESSION_SECRET` - Use a new random secret
- [ ] `RESEND_API_KEY` - Required for magic links to work
- [ ] `XERO_CLIENT_ID` - If using Xero integration
- [ ] `XERO_CLIENT_SECRET` - If using Xero integration
- [ ] `GTM_GOOGLE_CLIENT_ID` / `GTM_GOOGLE_CLIENT_SECRET` - Dedicated business-owned Google Tag Manager OAuth client

### Google Ads MCP control plane

The Google Ads MCP controls are four independent, false-by-default server flags:

```bash
GOOGLE_ADS_MCP_READ_ENABLED=false
GOOGLE_ADS_MCP_WRITE_ENABLED=false
GOOGLE_ADS_MCP_AUTOMATION_ENABLED=false
GOOGLE_ADS_MCP_DESTRUCTIVE_ENABLED=false
```

Enable read-only access first. Write access still uses tenant-bound action plans and approvals.
Automation applies only to policy-approved safe actions such as negative keywords or pauses.
`GOOGLE_ADS_MCP_DESTRUCTIVE_ENABLED` permits irreversible provider removal and should normally stay off.

## 🛠️ Troubleshooting

### "Authentication required" error on admin pages
1. Check secrets are set: `pnpm env:secrets:list:prod`
2. Verify `JWT_SECRET` and `SESSION_SECRET` are set
3. Clear browser cookies and try again

### Magic links not sending
1. Verify `RESEND_API_KEY` is set
2. Check Resend dashboard for domain verification
3. In development, check console for the magic link URL

### Database connection errors
1. Ensure you're using the **pooled** connection string from Neon
2. Check that `sslmode=require` is included
3. Verify the database user has proper permissions

### Xero OAuth not working
1. Check `XERO_CLIENT_ID` and `XERO_CLIENT_SECRET` are set
2. Verify redirect URI in Xero app matches your domain
3. Ensure Xero app is approved for the organization

## 📚 Additional Resources

### CRM search release-only bindings

CRM search release authority uses three unrelated bindings:

- `CRM_SEARCH_RESOURCE_APPROVAL_VERIFICATION_KEYRING` verifies trusted Ed25519 bootstrap approval envelopes.
- `CRM_SEARCH_RESOURCE_MANIFEST_VERIFICATION_KEYRING` verifies the exact preview/production Cloudflare resource manifest consumed by the Queue Worker.
- `CRM_SEARCH_SEALED_HOLDOUT_KEYRING` contains only AES-256-GCM sealed-holdout keys.

Never reuse `CRON_SECRET`, service-signing, confirmation, or analytics keys. Preview/production resource identities must be read back from Cloudflare and match the signed manifest. The sealed holdout remains blocked until the approved opaque object is imported to `crm-search/evaluation/holdouts/holdout-v1.json`, read back, and both the object and decrypted judgement SHA-256 values match. Do not put any of these values in `wrangler.toml`.
